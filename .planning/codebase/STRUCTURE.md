## Directory Purposes

**`src/`:**
- Purpose: All hand-written source. TypeScript for the Node process, `.jsx` for the AE process.
- Contains: Exactly one TypeScript module (`src/index.ts`) and the ExtendScript files.
- Key files: `src/index.ts` (963 lines — the whole server), `src/scripts/mcp-bridge-auto.jsx` (1773 lines — the whole AE side).

**`src/scripts/`:**
- Purpose: ExtendScript sources. Copied verbatim into `build/scripts/` by the `copyfiles -u 1 "src/scripts/**/*" build` step in the `build` npm script.
- Contains: One live bridge file plus ten standalone scripts.
- Key files: `src/scripts/mcp-bridge-auto.jsx` is the only file that participates in the MCP flow. The other ten are manual-run scripts whose functions are duplicated inside the bridge (see ARCHITECTURE.md "Legacy / not in the live path").

**`assets/`:**
- Purpose: Documentation images only.
- Contains: Screenshots/GIFs for `README.md`.
- Key files: None referenced by code.

**`build/`:**
- Purpose: Build output and the install payload.
- Contains: esbuild-bundled `index.js` (ESM, `--packages=external`) plus the copied `.jsx` files.
- Key files: `build/index.js` (what `.mcp.json` launches), `build/scripts/mcp-bridge-auto.jsx` (what `install-bridge.js` copies into AE).
- Generated: Yes. Committed: No.

**`.planning/`:**
- Purpose: GSD planning artifacts — analysis docs and the append-only backlog.
- Contains: `codebase/*.md`, `BACKLOG.md`.
- Generated: No (agent-maintained). Committed: Yes.

## Naming Conventions

**Files:**
- Node core: lowercase single module — `index.ts`. The installer is kebab-case — `install-bridge.js`.
- ExtendScript: camelCase matching the operation name — `applyEffect.jsx`, `setLayerProperties.jsx`, `createComposition.jsx`. The bridge is the exception: `mcp-bridge-auto.jsx` (kebab-case with a subsystem prefix), and it is the name the AE menu shows.

**MCP tool names (three inconsistent styles in one file):**
- kebab-case: `run-script`, `get-results`, `get-help`, `create-composition`, `apply-effect`, `apply-effect-template`, `run-bridge-test`
- camelCase matching the ExtendScript command: `setLayerKeyframe`, `setLayerExpression`, `test-animation`
- prefixed: `mcp_aftereffects_applyEffect`, `mcp_aftereffects_applyEffectTemplate`, `mcp_aftereffects_get_effects_help`
- New tools should follow kebab-case (`lower-case-with-dashes`), which is the MCP convention and the majority style.

**Command names (the wire contract):** camelCase, always identical to the ExtendScript function name — `createComposition`, `createTextLayer`, `setLayerProperties`, `batchSetLayerProperties`, `setCompositionProperties`, `duplicateLayer`, `deleteLayer`, `setLayerMask`, `setLayerKeyframe`, `setLayerExpression`, `applyEffect`, `applyEffectTemplate`, `bridgeTestEffects`, `createCamera`, `getProjectInfo`, `listCompositions`, `getLayerInfo`.

**Functions (ExtendScript):** camelCase verb-first (`createX`, `getX`, `setX`, `duplicateX`, `deleteX`). Helpers are `getCommandFilePath`, `getResultFilePath`, `updateCommandStatus`, `logToPanel`, `checkForCommands`, `executeCommand`, `startCommandChecker`.

**Variables:** camelCase. ExtendScript uses `var` exclusively (ES3). Args are always destructured off a single `args` object with `||` defaults, e.g. `var width = parseInt(args.width) || 1920;` in `src/scripts/mcp-bridge-auto.jsx:19`.

**Zod schemas:** PascalCase ending in `Schema` — `LayerIdentifierSchema`, `KeyframeValueSchema` (`src/index.ts:440-449`).

**Directories:** lowercase, single word — `src`, `scripts`, `assets`, `build`.

## Where to Add New Code

**New AE operation (the common case) — requires three coordinated edits, no new files:**
1. Write `function myOperation(args) { try { ... return JSON.stringify({ status: "success", ... }, null, 2); } catch (error) { return JSON.stringify({ status: "error", message: error.toString() }, null, 2); } }` inside `src/scripts/mcp-bridge-auto.jsx`, above `executeCommand`.
2. Add `case "myOperation": result = myOperation(args); break;` to the `switch` in `executeCommand` (`src/scripts/mcp-bridge-auto.jsx:1498`).
3. Add the MCP tool in `src/index.ts` that calls `writeCommandFile("myOperation", parameters)` and returns the "queued, poll `get-results`" message. Add the name to `allowedScripts` (`src/index.ts:173`) if it should also be reachable through `run-script`.
4. Update `build` output by re-running `npm run build`, then re-run `npm run install-bridge` so AE gets the new bridge (the installed copy is a snapshot, not a symlink).

**New MCP tool that maps to an existing command:** only step 3 — edit `src/index.ts`.

**New Zod-reusable argument shape:** add a `const XSchema = { ... }` near `LayerIdentifierSchema` in `src/index.ts:437` and spread it with `...XSchema` into each tool's schema (the existing one is spread at `src/index.ts:451` and `:489`).

**New standalone manual-run script:** create `src/scripts/myScript.jsx` only if a human must run it via File > Scripts. It reads its arguments from `../temp/args.json` (see `src/scripts/listCompositions.jsx:30`). The build's `copyfiles` glob picks it up automatically. Do not add a new file for anything that belongs on the bridge — the bridge is the single AE-side dispatcher.

**New MCP resource:** register with `server.resource("name", "aftereffects://name", handler)` in `src/index.ts`. If it needs data, follow the `compositions` pattern: `clearResultsFile()` -> `writeCommandFile(...)` -> `await waitForBridgeResult("<command>", 6000, 250)`.

**New MCP prompt:** `server.prompt("name", schema, handler)` in `src/index.ts`, returning `{ messages: [{ role: "user", content: { type: "text", text } }] }`.

**New installer target / AE version:** edit the `possiblePaths` ternary in `install-bridge.js:17` (`isMac` selects the macOS or Windows path list); the scan loop that consumes it is at `install-bridge.js:37`.

**Utilities:** there is no shared utils module. Small Node helpers live as module-level functions in `src/index.ts` (`getAETempDir`, `writeCommandFile`, `readResultsFromTempFile`, `clearResultsFile`, `waitForBridgeResult`). Keep it that way — a new `src/lib/` folder for five functions would be over-engineering.

## Special Directories

**`build/`:**
- Purpose: esbuild bundle + copied `.jsx`.
- Generated: Yes (`npm run build`, also via `postinstall`).
- Committed: No — never edit files here; edit `src/` and rebuild.

**`~/Documents/ae-mcp-bridge/` (outside the repo):**
- Purpose: The runtime rendezvous folder shared by the Node process and AE.
- Contains: `ae_command.json` (command + args + status) and `ae_mcp_result.json` (last result + `_responseTimestamp` + `_commandExecuted`).
- Generated: Yes, at runtime by both processes.
- Committed: No. Created on demand by `getAETempDir()` (`src/index.ts:25`) and by `getCommandFilePath()`/`getResultFilePath()` (`src/scripts/mcp-bridge-auto.jsx:1321`, `:1331`).

**After Effects `ScriptUI Panels/`:**
- Purpose: Where AE loads the bridge panel from (`.../Support Files/Scripts/ScriptUI Panels/mcp-bridge-auto.jsx` on Windows, `.../Scripts/ScriptUI Panels/` on macOS).
- Generated: No — populated by `npm run install-bridge`.
- Committed: No (lives outside the repo, inside the Adobe install).
